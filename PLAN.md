## 1. What we are building and why

**Aletheia** is an open-source, agent-agnostic memory for AI agents (Claude Code, Claude Desktop, Cursor, Cline, Codex, custom agents). Its one distinguishing idea:

> **Every memory is a claim plus evidence (anchors). Evidence is re-checked against the project's files on every recall. Stale memories never reach the agent's context.**

Why this gap exists (researched 2026-10-21):

- Mem0, Zep/Graphiti, Letta, Cognee, Supermemory compete on *storing and retrieving*. Benchmarks (LoCoMo, LongMemEval) measure recall, not whether recalled facts are still true.
- Similarity search ranks a stale fact as high as its replacement ("ghost context"). The STALE study found most agents fail to notice supersession. A memory that keeps a conclusion but drops its source becomes "confidently uncorrectable".
- Basic Memory already does "Markdown + MCP + SQLite index". That stack alone is **not** novel; the verification layer is.
- Name check: "cairn" and "muninn" are taken by several agent-memory projects; "aletheia" had no memory-project collision found via web search (GitHub search API was unavailable, so re-check before launch).

Positioning line: *"Memory that checks itself against reality."* Greek a-lḗtheia = "un-forgetting"; the GC command is named `lethe` (river of forgetting).

Non-goals for now: being a general knowledge base, chat-history memory, cloud sync, embeddings by default.

## 3. Architecture

```
cmd/aletheia/         CLI entry point, flag parsing, CLAUDE.md/AGENTS.md snippet (embedded)
internal/store/       Memory type, frontmatter (de)serialization, file store
internal/anchor/      Anchor parsing, sealing, checking (read-only, root-contained)
internal/search/      Tokenizer (6-rune prefix stemming), BM25, Jaccard
internal/engine/      Remember / Judge / Recall / Verify / Reseal / Lethe / Stats + rendering
internal/mcp/         Minimal MCP stdio server
scripts/gen_assets.py README images (pure stdlib Python)
```

Data flow of `recall`: list active memories → BM25 over (claim ×3, tags ×2, body) → top `limit×4` candidates → judge each against the files → hide stale → rank by relevance × confidence × freshness factor (1 / 0.7 / 0.3) → pack into budget (drop bodies first) → mark as sent for the session.

### Invariants: do not break these

1. **Markdown files are the single source of truth.** No index that can drift. If you add SQLite/FTS later, it must be a rebuildable cache under `.aletheia/.state/`.
2. **Verification never executes code** and never reads outside the project root. A poisoned memory file must not be able to run anything. (A `cmd:` anchor was deliberately left out.)
3. **A memory can never be saved in a state that contradicts its own anchors.**
4. **Nothing is deleted.** Superseded → archived. Users can delete files by hand.
5. **Zero dependencies** unless Fırat agrees otherwise.
6. **Token frugality:** one line per memory in recall, terse MCP descriptions, schema budget test stays.
7. Memory content is **data, not instructions** (stated in MCP `instructions` and the CLAUDE.md/AGENTS.md snippet).

### 4.5 Token-saving direction (decided with Fırat, 2026-10-21)
Aletheia has no claim yet. The goal is to **save tokens without losing quality**, because without a clear saving nobody has a reason to use it. Verification (stale memories never reach the agent) stays the differentiator, and the saving is built on top of it.

**What the data says** (R3 on expr-lang/expr, `docs/dogfood-4.2.md` §8):
- Every session starts at about 20k tokens of fixed context and grows to 40–50k.
- Billed cost splits roughly into cache reads 35–45% (turns × context), cache writes 30–40% (everything read gets written once), and output 25–30%.
- Memory can only cut reads and turns, so the realistic ceiling on edit tasks is about 20–40%.
- The one clear saving so far: a map memory made the next task of the same kind 40% cheaper, because the agent read a third as much before its first edit and needed fewer turns.

**Lessons from other projects:**
- **Aider's repo map:** an automatic, always-fresh, token-budgeted map, with no agent effort.
- **Codebase-Memory MCP:** about 10× fewer tokens on structural questions, but 83% answer quality. Savings can cost quality.
- **SWE-agent:** windowed reads beat whole-file reads, for focus as well as for cost.
- **ACE vs ALTK-Evolve:** injecting a whole playbook every step is expensive, and rewriting context wholesale loses information. Keep recall small and updates incremental, as we already do.
- **arXiv 2607.12161:** cutting tool-output tokens by 38% raised the bill by 7%, because agents compensated with more turns. Judge by **cost per successful task**, end to end.

**Plan, in order:**
1. **Automatic recall via hook.** `aletheia hook` for Claude Code's `UserPromptSubmit`: recall on the prompt text and inject the result. This saves the recall turn and guarantees memory is used. `init --agents` (or a flag) prints or installs the hook config.
2. **Live pointers in recall.** Memories that name symbols show their current `file:start-end` at recall time (e.g. `Builtins → builtin/registry.go:35-1081`), so the agent reads 15 lines instead of a 1000-line file. Pointers are computed on every recall, so they never go stale. Verified memory plus live pointers is what no competitor has.
3. **`symbol:` anchors** (pulled forward from v0.2). They are needed for 2, and they close the remaining false-`[ok]` classes (unused constant, name still present elsewhere). Use `go/parser` for Go (stdlib) and regex for other languages first.
4. **Automatic structure map.** An Aider-style ranked symbol map within a token budget, built without the agent writing anything. Use the stdlib only, cache it under `.aletheia/.state/`, rebuildable (invariant 1).
5. **Measure after each step** with the R3 harness (`lab-runs/r3/`), by cost per successful task:
   - one replicate per step for direction, 2–3 before any README number;
   - add task types where maps should help most: repeated change kinds and "how does X work?" architecture questions.

**Positioning until numbers exist:** "memory that never feeds the agent stale facts, and remembers how recurring changes are done". Make no token-saving claim before step 5 produces one.

## 5. Roadmap

**v0.2: smarter anchors**
- `symbol:PATH::Name`: anchor to a Go/TS/Python function or type by name so unrelated edits in the same file don't stale it (regex-based first, tree-sitter later only if Fırat accepts a dependency).
- Git awareness: optional `commit` field, follow renames (`git log --follow`) and suggest re-anchoring instead of just "missing".
- `aletheia doctor`: list memories whose `file:` anchors stale constantly and suggest `contains:`.

**v0.3: prove the token claim** (important for launch credibility)
- First run (R3, 2026-10-21, `docs/dogfood-4.2.md` §8): on expr-lang/expr, 4 tasks × 2 reps, Aletheia was **not cheaper** (+9% cost, +20% input tokens, same turns, 16/16 success both arms). Stale handling worked. Agents save gotchas, not navigation; next try navigation memories and mistake-avoidance tasks.
- R3-nav (map-memory rule, PR #3, 1 rep): break-even overall; the next same-kind task was 40% cheaper; no effect on a new kind of change. Follow-up plan: 4.5.
- R3-hook (PR #4) and R3-map (`feat/structure-map`, 1 rep each): the hook plus live pointers alone still broke even. With the code map added, the whole sequence was **15% cheaper than control**, every task below both control runs, 4/4 success. Next: replicate before any README number.
- Benchmark harness: run the same coding tasks with (a) no memory, (b) naive append-only memory, (c) Aletheia; measure input tokens per task and task success. Include a "stale trap" scenario (a fact changes mid-run). Publish method and numbers in the README; no numbers before this exists.

**v0.4: reach**
- Prebuilt binaries via releases, Homebrew tap, Scoop bucket (Fırat uses Windows + scoop), `npx @firatmio/aletheia` wrapper (npm name `aletheia` is taken; `aletheia-mem` was free on 2026-10-21).

- Optional local embeddings as a second ranking signal (keep BM25 default).

## 6. Known limitations and honest notes

- Tokenizer is a crude 6-rune prefix stemmer: works across English/Turkish inflections, misses synonyms. Good enough for short claims; embeddings would help.
- Recall rebuilds BM25 per query and judges up to 40 candidates by reading files. Fine to a few thousand memories; profile before scaling claims.
- `file:` anchors stale on *any* edit, including harmless ones. `contains:` is usually better; `--reseal` exists for the rest.
- No cross-process locking. Each file write is atomic, but `remember --supersedes` updates two files non-transactionally. Acceptable for one agent at a time; revisit for multi-agent use.
- `stats` token numbers are estimates (~4 chars/token). On tiny stores the "compact index" can be larger than the raw memories; that's expected.
- MCP: tools only (no resources/prompts), no batching, protocol versions 2024-11-05 through 2025-06-18 accepted.
- Symlink-escape test is skipped where symlinks are unavailable (often Windows without developer mode).
